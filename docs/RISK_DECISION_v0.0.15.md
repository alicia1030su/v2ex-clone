## 三、决策 B1（授权发布）的形态与纪律

| 项 | 约定 |
|---|---|
| 发布形态 | **公开 Pre-release**（强制 `prerelease=true`、`--latest=false`），**不是稳定版** |
| 触发方式 | 在**最终 SHA** 上创建 **annotated Tag `v0.0.15`** 并推送 ⇒ 流水线 `publish=true`；Tag **只创建一次**，不删除、不重建、不移动 |
| 前置条件 | 代码合并完成 + 版本载体统一到 `0.0.15` + 在该 SHA 上重新验证 + 产物来自该源码树 + SHA256 / Digest 可核验 |
| 发布包校验 | 包内 `VERSION=0.0.15`、compose 引用 `:v0.0.15`、`install.sh` 的 `APP_VERSION=0.0.15`、脚本含可执行位（N2 判据） |
| 发布后回填 | Tag 树记录的是**冻结时的候选状态**；公开发布结果（Release 可见性 / 资产 SHA256 / 镜像 Digest / 匿名拉取）在发布完成后以**独立文档提交**回填，**不移动 Tag** |

### 3.1 三种发行状态仍然分开陈述

1. **候选构建成功** —— run `42799071919`（SHA `33ba59f`）：镜像 / ZIP 能生成，SHA256 可核验；
2. **候选环境安装成功** —— 同一 run：`docker load` → `compose` → 全流程隔离安装通过；
3. **正式公开发布成功** —— 只能由**本次 Tag push 的发布流水线**与**发布后独立验收**给出。

**1、2 成功不代表 3 已完成。** 本文件授权的是 **3 的执行许可**，不是 **3 已经完成**的结论。

### 3.2 发布门禁例外（一次性，逐条登记）

| 例外项 | 事实 | 边界 |
|---|---|---|
| **24 小时单实例连续运行未完成** | GitHub-hosted runner 单 job 上限 6 小时；本机无 7×24 环境。已完成的是**口径修正**（区分分段累计与单实例连续）与可执行部分 | 不得把 1 小时冒充 24 小时；不得把「5 段累计」说成「单实例连续」；`docs/release-facts.json` 的 `soak.twentyFourHour` 保持 `not-completed` |
| **v0.0.14 已发布 Notes 的勘误** | 该版 Notes 有一行「待主人裁决」与「已获授权」矛盾 | **不修改已发布 Release**；只按 `docs/RELEASE_NOTES_ERRATA_v0.0.14.md` 披露 |
