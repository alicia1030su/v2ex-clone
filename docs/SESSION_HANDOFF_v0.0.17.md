## 2. 两处「任务前提与实测不符」——必须先说清

### 2.1 搜索分页**早就存在**

任务描述称「当前 `/go/search` 一次返回全部结果，没有分页」。实测（v0.0.14 起）：

```ts
parsePageParam(params.p) + limit(TOPICS_PER_PAGE) + offset(...)
+ count() + 上下两个 <Pager query={{ q }} />
```

⇒ 分页、总数、关键词跨页保留、`MAX_PAGE` 钳制**都已具备**。
本项真正修的是**分页的正确性**，不是「加一个分页」。

### 2.2 真缺陷：排序键不唯一 ⇒ 分页必然重/漏

```ts
.orderBy(desc(schema.topics.lastReplyAt))   // 修复前：只有这一个键
```

`lastReplyAt` 可以并列（同一秒的回复、或都没回复）。排序键不唯一时
PostgreSQL 的行序**没有保证**，而 `OFFSET/LIMIT` 分页依赖「稳定的总序」
⇒ 必然出现某页重复、某页遗漏。**种子数据十几条永远测不出来。**

修复：`.orderBy(desc(lastReplyAt), desc(id))` —— 排序键唯一，用户观感不变。

附带修正：节点/会员匹配原本在**每一页**都渲染同样 20 条
⇒ 翻到第 5 页仍看到同一批内容，会让人以为「翻页没生效」。
现改为 `page === 1` 才展示（搜索主体是主题，节点/会员属「相关入口」）。

## 3. P1-2：`/worldclock` 为什么**不加**导航入口

任务书写「仅当合理改善导航体验且不破坏高保真设计时增加入口」。实测与判断：

| 事实 | 结论 |
|---|---|
| `/worldclock` 已可从**页脚**进入（`#utc` / `#est` / `#pst` / `#cst` 4 处锚点） | 可达性**不缺失** |
| 原站顶栏只有「首页 / 热门 / 最新 / 节点 / 关于」等，**没有** worldclock 入口 | 加进顶栏会**偏离高保真** |
| 该页是原站的辅助页面，不属于主导航层级 | 属「功能已存在，位置合理」 |

⇒ **本轮不加**。若将来有证据表明原站某处存在该入口，再按实测补。
**不因为「任务书提到」就硬加一个原站没有的入口** —— 那会破坏高保真。

修改密码：三个框原本只有 `required`（浏览器静默拦截，用户点完没反应）。
现改为 `noValidate` + 提交处理里**逐项**校验，报错指出**具体哪一项**没填；
校验在发请求**之前**；消息区 `role="alert"` 可被读屏播报；
`required` 属性保留（辅助技术仍念「必填」）。

## 4. P0-1：运维后台的口径问题（本轮的重点不是"加个页面"）

### 4.1 计数是**进程内**的，不是集群总量

`/api/admin/ops` 的计数存在 `globalThis`（`src/lib/observability.ts`）。
多副本 / 多进程（cluster、PM2、k8s replicas）部署时，**每个实例各自计数**。
如果界面只画数字，运维会读成「全站 QPS 只有 30」，而真实可能是 30×N。

⇒ 接口新增 `scope`（契约）：

```
metrics: 'process'      // 只覆盖本进程
window:  'since-start'  // 累加窗口是「进程启动至今」，重启归零
instanceId / pid / startedAt / uptimeSeconds / nodeVersion / replicasDeclared
```

并附 `warnings` 三条，界面**必须渲染**（不只是接收）。
`replicasDeclared > 1` 时额外提示「以下数字只代表本实例」。

### 4.2 权限收紧：`ops.view`（仅 admin）

原接口挂 `config.view`（moderator 可见）。运维总览含**错误路由分布、
磁盘剩余、DB 连接数** —— 属基础设施面，版主不需要，且可被用来试探系统边界。
- 服务端：`adminGuard(request, 'ops.view')`
- 前端：tab `visibleTo: ['admin']`（**入口级**隐藏，不是点进去才说无权）
- 403 文案写「权限不足」，不写「加载失败」（否则版主以为系统坏了）

### 4.3 不伪造不存在的指标

| 指标 | 真实状况 | 界面表现 |
|---|---|---|
| 备份状态 / 上次成功时间 | **无数据源**：`backup.sh` 跑在宿主机，容器内不可见，也没有落盘记录 | 显示「**无数据源**」+ 原因，**不显示任何假状态** |
| 磁盘 | `statfs('/')` 可读 | 显示百分比；`<10%` 加警告；不可读时显示「不可读取」 |
| Redis | 未配置时走 PgKV 降级 | 显示「未配置（使用 PgKV 降级路径）」，**不显示为正常** |
| PG 连接 | 实时查 `pg_stat_activity` **聚合值** | total / active / idle / idleInTransaction / maxConnections |

`pg_stat_activity` **只取聚合值** —— 不透出 `query` / `client_addr` / `usename`。
返回体不含连接串、口令、Cookie、邮箱（E2E 逐项断言）。

## 5. P0-2：为什么要单独验证「原子性」

v0.0.16 修的是**假成功**（`ON_ERROR_STOP` 让退出码非零）。但退出码非零
**不等于**数据库没变：

> 一个中途失败、但已提交前 200 条 INSERT 的恢复，**退出码同样非零**。
> 运维看到「失败，重试即可」，而库里已是半截数据。

`scripts/release/verify-restore-atomicity.sh`（9 步）：

1. 隔离库写**带唯一标识**的用户 / 主题 / 回复
2. 采集指纹：业务表「行数 + 主键集合 md5」+ 结构「表.列.类型.可空 + 索引名」
3. 构造**合法但中途失败**的备份 —— 不是手搓假文件，而是**先真实 `pg_dump`**，
   再把失败语句插到**第 50% 行**（插在开头测不出「执行了一半」）
4. 恢复 ⇒ **必须非零**
5. 重读业务指纹
6. 重读结构指纹
7. 唯一标识行必须**仍然存在**
8. 重启应用 ⇒ 首页 200 且指纹不变
9. **三类失败面**分别验证退出码传递：截断 gzip / **管道中途失败** / SQL 失败

「管道中途失败」这一类最关键：`gzip -dc bad.gz | psql` 在没有 `pipefail` 时，
整体退出码取 psql 的 ⇒ gzip 死了但 psql 正常结束 ⇒ 判成功。

## 6. P0-3：候选包为什么必须可复现

v0.0.16 候选包用 `zip -qr`，`zip` 把文件**实际 mtime** 写进 ZIP 头
⇒ 同一源码三次构建得到三个不同 SHA256：

```
0b8242b20b27d841292b1ff92142e1ccafd8d0398e43ce4153bdf041576b2ffe
b6f766671e71fec081d751f709bc0f422e04208fd9a9d4472583a8528de34870
5b52c17d385b630e885c10d344d118a9309f3b29e69831d889a659b217c740e3
```

后果不是「哈希好看不好看」：**无法用 SHA256 证明「验收过的那份」就是「发布的这份」**。

修法：候选包改用**正式包的打包器** `package-deploy-zip.mjs`
（固定时间戳 / 固定条目顺序 / 固定 Unix mode / store 模式），
新增 `--name candidate` 参数区分命名。

**不要求**候选包与正式包字节相同（镜像引用与文件名不同，本来就不是同一产物）；
要求的是**各自可复现 + 共用可审计规则**。

顺带修打包器：`--src` 原来只支持相对路径，绝对路径会被接在 ROOT 后面 ⇒ `ENOENT`。
**回归证据**：改动后重打 v0.0.16 正式包，SHA256 仍是
`09700425d9c0bc25b25154702509fd9902dd93dd5fdd26cfb0c85b771bcdd274`。

本次授权**没有**被用来改写这个事实。

### 本轮真正修掉的长跑缺陷：把「没测到」写成「0」

已有证据 `perf-samples.csv`（run 44296152975）：

```
ts,elapsed_s,mem_mb,cpu_pct,conn_used,conn_max,home_ms,db_ms
2026-11-18T11:46:04Z,541,0.0,0.0,,,00,4
```

汇总写「峰值内存：0 MB」「峰值PG连接：0」。**这不是测到 0，是没测到**：
1. `ps -o rss= -C node` 按**命令名精确匹配**，而实际进程名是 `next-server (v15.5.28)`；
2. `awk` 对**空输入**仍输出 `0.0`（`s` 为空 ⇒ `0/1024`）。

`0 MB` 看起来像结论（「这服务几乎不占内存」），实际是**采集失败**。
修法：`pgrep -f 'next-server|next start'` 按命令行匹配；awk 用 `NF` 判空；
取不到时汇总写「**未采集（采集失败不是 0）**」。
