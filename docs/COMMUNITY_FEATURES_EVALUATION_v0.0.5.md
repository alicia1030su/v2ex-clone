# v0.0.5 社区能力评估报告（私信与其他）

> 任务书 §十要求：**先确认原站公开可观察的行为和当前项目现有功能**，
> 再决定哪些纳入本轮；并明确「多语言、站内 RSS 阅读器等**非核心扩展**，
> **不得为了功能数量而盲目开发**」。
>
> 本报告就是这份「先确认、再决定」的记录。

## 一、结论先行

| 能力 | 原站有吗 | 本站有吗 | 本轮决定 | 理由 |
|---|---|---|---|---|
| **站内私信 / 消息中心** | ❌ **没有** | ❌ 没有 | **不做** | 原站**根本没有**这个功能 —— 造一个就是凭空发明 |
| **@ 提及通知** | ⚠️ 靠**手写 Markdown 链接**（非自动功能） | ⚠️ **半成品**（schema 有、UI 有、**生成逻辑没有**） | ✅ **本轮补齐** | 论坛标准互动方式，且数据模型**已预留**位置 |
| 多语言 | ✅ 有独立页 `/select/language` | ❌ 无 | **不做** | 非核心扩展；任务书点名不得盲目开发 |
| 站内 RSS 阅读器 | — | ❌ 无 | **不做** | 任务书点名不得盲目开发 |
| 私信之外的其它社区能力 | — | — | 留待后续评估 | 本轮只补齐**已存在半成品**的那一个 |

**一句话**：私信**不属于**本项目要还原的社区形态；本轮用 **@ 提及** 补齐了那个「有 UI 没实现」的半成品。

## 二、私信：原站**实测没有**这个功能

### 2.1 证据：登录态首页的导航链接里没有任何私信入口

原站快照（`docs/evidence/html/d_index.html`，**登录态**）里提取出的全部导航链接：

```
/nodes  /go  /recent  /hot  /feed  /bookmarks  /values
/topic  /member  /settings  /help  /about  ...
```

**没有**「私信」「消息中心」「收件箱」「messages」「inbox」任何一项。

> 判定依据：登录态快照是**最有说服力**的证据 —— 未登录时看不到私信入口是正常的，
> 登录后还看不到 ⇒ 确实不存在。

### 2.2 反向验证：全快照搜索

```
grep -ril "私信|消息中心|收件箱|conversation|inbox" docs/evidence/html/
→ 仅 1 个命中：d_topics.html
```

逐条检查该命中 —— 是 CSS 类名 / 无关注释词里的 `inbox` 字样，
**与私信功能无关**。

### 2.3 V2EX 的实际交流模型

V2EX 是「**回复驱动**」的论坛：

- A 在主题下回复 B ⇒ B 收到 `reply` 通知
- B 看到通知后回到主题继续对话

**没有私信的语义**。想「私下说」的办法就是开一个主题 —— 这正是 V2EX 的文化。

### 2.4 原站的「叫某人」是**手写 Markdown 链接**

原站快照里的成员链接形态：

```html
<a href="/member/reoah2">reoah2</a>
```

即：原站的「@ 某人」是**用户自己在正文里手写链接**，**不是自动功能**。

> 这是一个重要事实：原站**也没有**自动 @ 提及。
> 但这不意味着我们不能做 —— 详见 §三。

## 三、@ 提及：补齐**已存在的半成品**

### 3.1 为什么做（不是盲目加功能）

本站的 `notifications` 表**一直有** `mention` 这个类型：

- `src/db/schema.ts` —— 枚举里有 `mention`
- `src/components/NotificationsList.tsx` —— UI 里**一直有**「提及」的中文标签

但**从来没有代码写入过它**。

也就是说，本站存在一个**「UI 能显示、但永远不会出现」**的通知类型。
这不是「缺功能」，而是**功能做了一半** —— 属于「半成品」而非「新增」。

### 3.2 为什么不用私信替代

| 维度 | 私信 | @ 提及 |
|---|---|---|
| 原站是否支持 | ❌ 没有 | ⚠️ 靠手写链接（但**论坛惯例**是这么用的） |
| 数据模型 | 无（要新建 3 张表） | ✅ **已预留** `mention` 类型 |
| UI | 无（要新建） | ✅ **已存在**「提及」标签 |
| 社区形态契合度 | ❌ 违背 V2EX 的「回复驱动」文化 | ✅ 标准互动方式 |
| 复杂度 | 高（新表 + 消息状态 + 已读未读 + 会话列表） | 低（复用现有通知管道） |

### 3.3 实现

**`src/lib/mentions.ts`（新）**

```ts
extractMentions(content: string): string[]
buildMentionMessage({ actorName, topicTitle, isReply, floor }): string
```

解析规则：`@` + 2–32 位字母数字下划线，**带单词边界**
（所以 `foo@example.com` 里的 `example` **不是**提及）。

**`src/app/api/replies/route.ts`**

在「通知主题作者」之后追加提及通知写入。

#### 边界（全部有测试守护）

| 边界 | 规则 | 理由 |
|---|---|---|
| 只对**真实存在**的用户发 | 查不到就忽略 | 否则可被用来刷通知表 |
| 不给自己发 | `ne(users.id, user.id)` | 自己 @ 自己没意义 |
| 去重 | 同一条内容里 @ 同一用户只通知一次 | 避免刷屏 |
| 数量上限 | 单条内容**最多 10 个** | 防「@ 一百个人」刷爆通知表 |
| 不是安全边界 | 提及里的用户名按普通文本渲染 | Markdown 已经过 `sanitize-html` 清洗 |

### 3.4 实现过程中发现并修复的**真实缺陷**

#### BUG-15：合法用户名的 @ 提及**静默失效**

`mentions.ts` 的 `USERNAME_RE` 写的是 `{3,20}`，
而 `signup/route.ts` 允许的是 `{2,32}`。

⇒ **13–32 字符的合法用户名永远无法被提及**，
而且用户**得不到任何提示**（@ 了，但什么也没发生）。

实测证据：E2E 用的 `uniqueName('ment_a')` 生成了 23 字符的用户名
（`ment_a_mw480sax17sbynw`）⇒ 匹配不上 ⇒ **一个 mention 通知都没产生**。

**修法**：与注册校验逐字对齐为 `{2,32}`，
并加**一致性守护测试**（解析两处源码里的正则，
断言长度区间**完全相同**）⇒ 将来任何一边改了，另一边没跟上，测试立刻红。

> 这正是「先测后修」的典型：单元测试全绿（18 条），
> 但 E2E 一跑就抓到了 —— 因为**单元测试用的样本恰好都在 20 字符以内**。

## 四、明确**不做**的项（以及为什么）

### 4.1 多语言

原站有独立的 `/select/language` 页面（独立站点式的多语言）。
本站是**单语言中文社区**。

**不做**的理由：
- 任务书 §十明确点名「多语言……等非核心扩展，不得为了功能数量而盲目开发」
- 多语言需要 i18n 框架、全量文案抽取、语言包、RTL 适配
  —— 这是**一个独立项目**，不是一个功能点
- 本站的文案高度依赖中文社区语境（节点名、术语、口语）

**将来若要做**：应作为独立里程碑，且**不阻塞** v0.0.5。

### 4.2 站内 RSS 阅读器

任务书同样点名。本站已有 **RSS 输出**（如果有），
但「站内读别人的 RSS」是**内容聚合器**的功能 ——
与「社区论坛」是两种产品形态。

**不做**。

### 4.3 私信

理由已在 §二 详述：**原站没有**。

造一个私信系统需要：会话表 + 消息表 + 已读状态 + 会话列表页 + 未读计数 +
权限边界 + 举报滥用防护……
而且它会**改变社区形态**（从公开讨论变成私域讨论）。

**除非主理人明确要求**，否则不做。

## 六、已知限制（如实记录）

1. **@ 提及只在回复里触发，不在主题里触发** —— 与 V2EX 习惯一致
   （主题没有「回复者」这个角色）。
2. **提及通知不区分「@ 了但用户名拼错」** —— 拼错就查不到用户，
   静默忽略（与 V2EX 原站的「手写链接拼错」表现一致）。
3. **没有「提及列表」页** —— 只能从通知中心看到。
4. **WebKit ≠ 真实 Safari**（P1-4 已在 `CROSS_BROWSER_VISUAL_REPORT_v0.0.5.md` 标注）。
5. **未做真实外部 SMTP 的提及通知投递** —— 提及通知走站内通知表，不发邮件。

## 七、复现方式

```bash
# 单元测试
bash tests/helpers/start-test-pg.sh start
npx vitest run tests/v005-mentions.spec.ts

# E2E（需要先 build + 启动应用，见 docs/SESSION_HANDOFF_v0.0.5.md §E）
npx playwright test e2e/v005-mentions.spec.ts --reporter=list
```

> ⚠️ 跑 E2E 前**必须**让服务端与测试进程用**同一个** `DEBUG_ENDPOINT_TOKEN`
> —— 否则 `clearRateLimits` 静默失效，注册会撞限流，
> 而报错表现是「等满 30 秒的 TimeoutError」，完全指不到真正原因。
> 详见 `e2e/helpers.ts` 的 `debugTokens()`。
