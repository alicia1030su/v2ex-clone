## 五、授权后的发布形态与纪律

| 项 | 约定 |
|---|---|
| 发布形态 | **公开 Pre-release**（强制 `prerelease=true`、`--latest=false`），**不是稳定版** |
| 触发方式 | 在**最终 SHA** 上创建 annotated Tag `v0.0.14` 并推送 ⇒ 流水线 `publish=true` |
| Tag 纪律 | `v0.0.14` Tag **只创建一次**，不删除、不重建、不移动 |
| 前置条件 | 代码合并完成 + 版本载体统一到 `0.0.14` + 在该 SHA 上重新验证 + 产物来自该源码树 + SHA256/Digest 可核验 |
| 发布包校验 | 包内 `VERSION=0.0.14`、compose 引用 `:v0.0.14`、文档首行与全部头部注释均为 `v0.0.14`（N2 等价判据） |
| 发布后回填 | Tag 树记录的是**冻结时的候选状态**；公开发布结果（Release 可见性 / 资产 / Digest / 匿名拉取）在发布完成后以**独立文档提交**回填，**不移动 Tag** |

### 5.1 三种发行状态仍然分开陈述

1. **候选构建成功** —— 镜像 / ZIP 能生成，SHA256 可核验；
2. **候选环境安装成功** —— 干净 Linux 上能起容器、能注册登录发帖、能原地升级并保留数据；
3. **正式公开发布成功** —— Tag 已创建、公开 Pre-release 可见、匿名下载 / 匿名拉取通过。

**1、2 成功不代表 3 已完成。** 本文件授权的是 **3 的执行许可**，
不是 **3 已经完成**的结论；3 的结论只能由发布流水线与发布后独立核验给出。
