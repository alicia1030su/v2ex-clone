## 五、本轮修复的关键缺陷：API 错误率统计失效

这是本轮**最有价值**的发现 —— 它让 §六「API 5xx 是否能够被统计」从
「声称支持」变成「真的支持」。

**两个叠加缺陷**：

1. Next.js 把 `middleware.ts` 编译成**独立 webpack bundle**，
   与路由处理器**不共享模块实例** ⇒ 模块级 `Map` 被求值两次 ⇒
   `api.requests` **恒为 0**；
2. `NextResponse.next()` 返回的是 middleware 自己的响应（恒 200），
   下游真实响应会替换它 ⇒ `byStatus` **恒为 `{200: N}`**。

**修复**（三处必须同时存在）：
`globalThis` 桥接 + `runtime = 'nodejs'` + `instrumentation.ts`
（Node HTTP 层拿真实 statusCode）。

**实测**：`api.requests=13`、`byStatus={'200':4,'401':2,'404':1}`、
`error4xxByRoute` 按路由聚合。

## 八、Go / No-Go 结论

### 🟡 有条件 Go（建议：合并 PR + 继续候选化，暂不正式发布）

**支持 Go 的依据**：

1. **候选交付链完整闭环** —— 候选镜像构建、tar 导出、ZIP + SHA256、
   独立环境 `docker load`、Compose 启动、迁移 / Redis / 健康检查 /
   登录 / 发帖 / 回复 / 重启不丢数据 —— **全部在真实 Docker 上验证过**；
2. **v0.0.4 → v0.0.9 升级的数据完整性是逐字节证明的**，
   不是「跑通了」的定性说法；
3. **修复了一个此前让运维失明的严重缺陷**（错误率统计恒为 0）；
4. **R-01 的隔离副本演练证明**：清理历史**不损坏项目**
   （业务代码 blob SHA256 不变 + 清理后仍可编译），
   且**已发布的安装包与镜像本来就不含受影响素材**；
5. 门禁纪律有效 —— CI 实跑暴露 5 个缺陷全部修复，无一被绕过。

**不建议现在正式发布的依据**：

1. **R-01 维持 DEFERRED** —— 4 个已发布 Tag 仍使素材可达；
   虽已确认用户可获得面干净，但**改写历史也无法消除已下载/已缓存的内容**；
2. **正式发布授权未获得** —— 模式 A（GHCR 推送 + digest + 匿名 pull +
   正式 Release + Tag）需要单独签字；
3. **24 小时长跑尚未跑完** —— 任务书 §七 明确禁止在未实际跑完时标注达成。
