# v0.0.10 发布死锁（如实记录）

## 事实链

1. Tag `v0.0.10` → `7ea8e64`，其中 `deploy/README.md` 标题行是
   `# V2EX Clone v0.0.9 — 一键部署包`（该文件从未被 `sync-version.mjs` 覆盖）。
2. 发布流水线的 N2「包内版本一致性校验」要求包内该标题 = `v0.0.10`
   ⇒ 从 Tag 内容打包必然失败。
3. 补救路径（`workflow_dispatch` 从 master 构建）要求
   `git diff TAG_SHA..master -- deploy/ src/ ...` **零差异**。
   而修好该文件必然改动 `deploy/` ⇒ 补救路径必然失败。

**⇒ 二者不可同时满足。** Tag 内容与 N2 判据互斥。

## 两个可选出口

| 出口 | 代价 | 是否违反规约 |
|---|---|---|
| A. 重建 Tag `v0.0.10` 指向修好的提交 | 需 `git tag -f` + force push Tag | **违反**「Tag 创建后不能移动或删除重建」（需单独授权） |
| B. 改发 `v0.0.11`（内容 = v0.0.10 + 载体修复） | 交付版本号与任务书目标不一致 | 不违反任何规约 |

## 已确认的其它事实

- `v0.0.10` **没有** Release（`release not found`）
- 镜像**未**匿名可拉（`manifest=401` ⇒ 包不是 public，或尚未推送成功到公开包）
- 因此 **v0.0.10 对用户而言尚不存在**，重建 Tag 不会影响任何已下载用户
