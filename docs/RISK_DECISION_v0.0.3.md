## 二、阻断项详情：Git 历史中的原站素材

### 2.1 事实（本轮重新匿名实测，无凭据、无代理）

| 路径 | HTTP 状态 |
|---|---|
| `75c9508/docs/evidence/assets/combo.js` | **200** ⚠️ |
| `75c9508/docs/evidence/assets/combo.css` | **200** ⚠️ |
| `75c9508/docs/evidence/html/home.html` | **200** ⚠️ |
| `75c9508/docs/evidence/screenshots/ref-home.png` | **200** ⚠️ |
| `master` / `v0.0.1` / `v0.0.2` 的上述路径 | 404 ✅（当前树与两个 tag 树已无这些文件） |

`75c9508` 是仓库的**根提交**，一次性引入了 **48 个**原站素材文件
（完整 HTML/CSS/JS 副本 + 40 张像素级参考截图 + 10 张差异热力图）。

### 2.2 为什么当前状态无法自动修复

`75c9508` 是**所有远端引用的共同祖先**。要让素材不再可达，必须：

| 方案 | 操作 | 授权状态 |
|---|---|---|
| A | 改写全部 refs 的历史（`git filter-repo` + 强推） | ⛔ 明令禁止（改写远端历史 / force push） |
| B | 移动或删除 `v0.0.1` tag | ⛔ 明令禁止（移动已有 Tag） |
| C | 删除仓库重建 | ⛔ 明令禁止（删除仓库） |

**本轮未执行上述任何操作。**

### 2.3 关键事实（影响方案选择）

- **`v0.0.1` tag 的存在使可达对象数增加**：tag 对象本身指向一个 commit 树，
  即使改写 master 与开发分支，**不动 v0.0.1 tag 仍会让素材可达**。
  这是「历史清理演练早于 v0.0.1 Tag 创建」造成的**时序约束**，
  必须重新评估清理范围。
- **不能说「没人获取过」**：v0.0.1 的资产下载数已变为 zip 3 次 / SHA256SUMS 4 次，
  且匿名 raw 访问**不产生任何计数** —— 无法据此论证无人获取。
- **当前 HEAD 的文件树是干净的**：已追踪文件中受控证据素材数量为 **0**，
  `.dockerignore` 也已排除这些路径 —— **新发布的镜像不含原站素材**。
