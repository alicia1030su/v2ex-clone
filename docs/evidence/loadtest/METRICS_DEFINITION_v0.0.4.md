## 二、leaderboard 三个数值的统一解释

| 数值 | 测量条件 | 含义 | 可否作为达标值 |
|---|---|---|---|
| **241.98 秒** | 单条 SQL、`EXPLAIN ANALYZE`、优化**前** | 相关子查询对每个作者执行一次（loops=9997），全表扫 thanks | 优化前基线，非达标值 |
| **0.74 秒** | 同上、改写为「三个独立聚合 + JOIN」后 | 单次 SQL 执行时间 | 单次查询口径 |
| **0.46 秒** | 同上、再加 `0002` 的部分索引后 | 单次 SQL 执行时间 | 单次查询口径（最优） |
| **p50 1233.8ms / p95 1530.1ms / avg 1164.7ms** | HTTP 端点 `/api/leaderboard?limit=50`、**并发 10、持续 20s、174 次请求** | 完整请求链路（HTTP + Next 渲染 + DB + 连接池竞争） | ✅ **用户可感知延迟，对外只用这一组** |

**结论**：`0.46s` 是「数据库单次查询」，`1.16~1.53s` 是「并发下的 HTTP 端点」——
两者测量对象不同，**不矛盾**。对外声明性能时统一采用压测口径：
「排行榜 API 在 10 万主题 / 100 万回复、并发 10 下 avg 1165ms、p95 1530ms，
相比优化前的 242 秒（不可用）提升约 200 倍」。
单次 SQL 的 0.46s 仅作为「索引有效性」的证据保留。

## 四、错误率口径（D-06）

| 项 | 值 |
|---|---|
| 总请求 | 24785 |
| 总错误 | **412（1.66%）** |
| 5xx 错误 | **0** |
| 错误构成 | 全部为 **404**：大型帖回复分页 104、主题详情 API 308 |
| 根因 | 压测器用**随机 id** 构造 `/t/{id}` 与 `/api/topics/{id}`，命中越界 id 或被软删除的主题（压测库有 5% 软删除） |
| 是否应用缺陷 | **否**。404 是「资源不存在」的正确响应；随机 id 越界属于测试数据构造方式 |

**通过标准（固定口径）**：

- ✅ **5xx 率 = 0** —— 硬性门禁，任何 5xx 即 No-Go
- ✅ **写路径错误率 = 0** —— 并发发帖/回复各 50 请求、0 错误（含重复楼层 0、账本不自洽 0）
- ✅ **业务错误率**：排除「随机 id 越界 / 软删除导致的 404」后为 0
- ⚠️ 原始错误率 1.66% 必须**连同口径一起披露**，不能单独宣称「错误率 0」

> 后续改进（不在本轮）：压测器可从 `/api/topics` 拉一批真实 id 再构造 URL，
> 使原始错误率也接近 0；但**不能为了让数字好看而把 404 静默丢弃**。
